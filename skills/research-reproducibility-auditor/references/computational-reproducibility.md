# 计算复现审计

用于只读检查分析项目能否从明确输入重建关键输出。审计默认不执行项目代码；“结构上具备复现条件”和“已经真实重跑成功”必须分开报告。

## 证据清单

- 明确的入口命令、运行顺序或工作流定义；
- 输入数据清单、来源、版本、许可、校验和及获取方式；
- 代码版本、提交或发布标识，以及未提交修改状态；
- 依赖清单与锁定文件，包括语言、运行时、系统库和外部 CLI；
- 配置、环境变量和秘密信息的文档化替代说明；
- 随机种子、非确定性算子、并行性和硬件差异；
- 绝对路径、机器专用目录、区域设置、时区、编码和操作系统假设；
- 中间产物、缓存、手工编辑步骤和外部服务调用；
- 每个关键表格、图形、模型或报告到生成代码和输入的追踪关系；
- 预期退出状态、测试、关键输出摘要或哈希比较方法。

## 只读检查

根据项目技术栈选择必要检查，例如列出文件、搜索路径或环境变量引用、读取清单和锁文件、检查 Git 状态、计算用户授权范围内文件的哈希。不要把下列操作描述成只读：

- 执行 Notebook、分析脚本、Makefile、工作流或测试套件；
- 构建镜像、安装依赖、恢复环境或下载数据；
- 渲染 Quarto、LaTeX、报告或站点；
- 清理缓存、重新生成输出或更新锁文件。

如用户要求真实复现，先确定隔离副本、写入目录、预计下载、计算成本和外部服务；得到所需授权后再运行。保留命令、版本、退出码、日志位置、输出哈希和与基准的差异。

## 判断层级

- `材料结构可审计`：入口、输入、依赖和输出链路可定位，但没有真实执行。
- `局部运行已验证`：只验证了部分步骤或样例数据，明确未覆盖范围。
- `完整重跑已验证`：在干净或等价环境中从规定输入生成关键输出，并完成约定比较。
- `无法判定`：缺少数据、依赖、权限、基准产物或关键说明。

不要因存在 Dockerfile、锁文件、CI 徽章或测试就升级为“完整重跑已验证”。
