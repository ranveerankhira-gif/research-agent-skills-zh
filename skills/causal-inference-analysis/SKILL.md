# 因果推断分析

把因果问题、识别假设、研究设计、估计方法和统计不确定性分开处理。本 Skill 只允许通过 `$causal-inference-analysis` 显式调用；“影响”“驱动因素”等含糊商业用语不足以构成调用理由，除非用户确实要求因果效应。

## 先定义目标

在选择模型前定义：目标人群、处理/暴露、比较条件、分配时间、随访起点、结果、时间范围、估计量（如 ATE/ATT/LATE）和分析单位。观察性关联问题不能通过换一个回归名称自动变成因果问题。

用领域知识描述因果结构；DAG 是假设的透明表达，不是从数据自动证明的真相。识别混杂、媒介、碰撞点、选择机制和时间变化变量。不得为了提高拟合度盲目控制处理后的变量、媒介或碰撞点。

方法选择见 [references/design-methods.md](references/design-methods.md)；诊断、敏感性分析和报告见 [references/diagnostics-reporting.md](references/diagnostics-reporting.md)。

## 核心原则

1. 先说明“在什么假设下可识别”，再计算效应。
2. 数据不能直接检验无未测混杂、排除限制等关键假设；可做诊断和敏感性分析，但不能把它们误称为证明。
3. 设计阶段优先：时间顺序、处理定义、可比组、重叠和负对照通常比更复杂的结果模型重要。
4. 平衡、拟合或显著性良好不等于因果识别成立。
5. 报告效应量、置信/可信区间、目标估计量、识别假设、诊断、敏感性分析和适用边界，不只报 p 值。
6. 若处理会影响删失、缺失、参与或测量，需要把这些机制纳入因果结构，而不是简单完整案例分析。

## 数据与执行边界

- 不虚构变量、处理时点、政策实施、工具变量、带宽、平行趋势或反事实结果。
- 在真实数据上估计前，确认数据字典、时间单位、重复测量/聚类结构、缺失编码、处理版本和目标样本。
- 方案设计和方法审计默认只读。读取真实数据前确认输入范围；生成代码、图表或结果文件前确认输出目录。只创建新产物，不覆盖现有分析文件。
- 不自动下载受限数据、安装统计包、调用收费平台、上传机密数据、启动远程计算或修改原始数据。需要这些动作时分别说明并取得当前授权。
- 预测准确率、特征重要性、SHAP 值或相关系数不能直接解释为因果效应。

## 与其他 Skill 的边界

- 随机试验、随机化、区组和实验处理结构由 `experimental-design` 负责；本 Skill 可帮助定义估计量和偏离后的因果分析。
- `statistical-analysis` 可执行一般模型、诊断和不确定性计算；本 Skill 负责识别逻辑、方法特定假设和因果解释。
- 系统综述或元分析中的因果证据综合分别由 `literature-review` 和 `meta-analysis` 处理。

## 交付

按任务交付目标试验表、DAG 假设清单、识别策略、变量角色表、估计方案、代码、平衡/重叠/趋势诊断、敏感性分析、结果解释或审计报告。每个因果结论必须附带其依赖的设计事实和不可验证假设；证据不足时返回关联性结论或 `causal_identification_not_supported`，不能硬凑因果答案。
