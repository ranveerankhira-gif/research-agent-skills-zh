# 去重、冲突与版本关系

## 确定重复

相同的规范化 DOI、PMID、PMCID 或 arXiv ID 可以形成确定重复候选，但合并前仍要检查记录是否把标识符填错。相同 CSL `id` 不是合并信号，而是库完整性错误，应先修复键冲突。

确定重复记录之间若作者、标题、年份或载体冲突，保留全部原始记录并列出冲突；不要采用“字段最多的一条就是正确”的捷径。

## 可能重复

规范化标题与年份相同、或标题高度相似但标识符不同，只标记为可能重复。会议论文扩展为期刊论文、勘误、评论与原文、同题不同语言版本都可能产生相似标题。

## 版本关系

分别保存预印本、接受稿、正式版本、会议摘要、注册记录、更正和撤稿通知的标识符。建立 `related` 或外部台账说明关系，例如 `is-preprint-of`、`is-correction-of`、`is-retraction-of`，不要删除被替代版本的溯源信息。

实际引用哪一版由主张、可访问性、期刊要求和记录状态决定。正式版通常优先，但若主张只出现在预印本或版本结果发生变化，应明确说明。

## 引文键

引文键只用于库内引用，不是文献身份。键变化不能被当作新文献，键相同也不能证明同一文献。重建键前先保留旧键到新键的映射，避免正文引用断裂。
