# 科学论文写作

从用户提供或已经核验的研究材料生成科学稿件，同时保持证据、数字、方法和声明可追溯。允许自动调用，但限于“从材料起草新稿或新章节”；已有文稿的诊断、润色、修改、审稿或回复审稿人交给 `paper-review-reviser`。

不要因普通写作、科普文章、文献综述、找论文、引用核验、统计分析、基金申请或规避 AI 检测而自动调用。综述证据由 `literature-review` 处理，引用身份和主张支持由 `literature-evidence-checker` 核查，引文库整理交给 `citation-management`，新统计结果交给 `statistical-analysis`。

## 写作前

先确认文稿类型、研究设计、目标读者、语言、章节范围、目标期刊或格式要求、研究阶段以及可使用材料。按需读取 [references/evidence-intake.md](references/evidence-intake.md)，把材料区分为：

- `已核验`：可定位到原始数据、分析输出、研究记录或已核验来源；
- `待核验`：存在题录、摘要、片段或未经复核的陈述；
- `材料缺失`：起草该内容所需资料尚未提供。

如果用户只提供研究主题而没有真实研究材料，可以给结构、问题清单或带明确占位符的示例框架，不得把它写成已经完成的真实研究。

## 起草原则

1. 先把研究问题、设计、方法、分析、结果和结论建立对应关系，再组织文字。缺口保留为醒目的 `【材料缺失：……】` 或 `【待核验：……】`。
2. 方法写实际做过的内容，不用“更理想的方法”悄悄改写研究记录。结果只来自已有数据、表格或分析输出，不补做未授权计算。
3. 数字、单位、样本量、分母、分析人群、时间点、组名和结局名称在摘要、正文、图表之间保持一致；发现冲突时列出冲突，不自行挑一个数。
4. 引言与讨论中的外部事实绑定已核验来源。搜索摘要、生成式总结和另一篇文章的参考文献表可用于发现来源，但不是主张已经得到支持的证明。
5. 根据研究设计和目标期刊选择结构，不把 IMRAD 当作所有文章的唯一结构。具体章节边界见 [references/section-writing.md](references/section-writing.md)。
6. 保留不确定性、替代解释、阴性结果、不良结果和适用范围，不把相关性强化为因果，也不把“不显著”改写成“无效”或“等效”。

## 科研诚信门禁

- 不捏造引用、DOI、引语、页码、数据、样本量、效应值、置信区间、P 值、模型、软件版本或实验细节。
- 不捏造伦理审批、注册、知情同意、作者、作者顺序、CRediT 贡献、基金、利益冲突、致谢、数据/代码可用性或 AI 使用声明。
- 不根据结果方向隐藏研究、分析、偏离、失败、异常或不利事件。
- 不把报告指南的检查表通过解释成研究质量、完整合规或期刊接收保证。
- 不向外部服务发送未发表稿件、审稿材料、个人信息、受限数据或专有材料；外传需要具备权限的人明确授权并满足机构与期刊政策。
- 不替作者批准投稿、作者顺序、科学争议或披露内容。最终科学判断与提交由真实作者确认。

作者、保密、报告指南与开放科学的处理见 [references/reporting-integrity.md](references/reporting-integrity.md)。

## 权限与文件安全

- 只读取用户明确指定的研究材料，不扫描相邻目录、文献库、邮箱、浏览器、云盘或其他研究项目。元数据或局部摘录足够时，不读取完整敏感数据集。
- 只有用户要求核对当前期刊规范、报告指南或公开来源时才联网；只访问公开官方来源，不登录投稿系统、不上传稿件或研究材料，并记录来源与访问日期。
- 默认在回复中交付草稿。用户要求文件时，先确认目标路径并创建新文件；同名文件存在时停止，不覆盖原稿、原始数据、分析输出或既有图表。
- 起草请求不授权运行统计分析、修改数据、生成缺失结果、创建外部项目或提交稿件；这些操作必须另行明确要求，并遵守对应专用 Skill 的权限边界。

## 交付

交付起草文本时同时给出：使用了哪些材料、仍缺什么、哪些陈述待核验、数字或方法冲突、作者需确认的科学判断，以及适用的报告指南/期刊要求是否已核对。若用户要求纯净稿件，可将审计说明放在稿件之后，但不得删掉未解决的事实缺口。
