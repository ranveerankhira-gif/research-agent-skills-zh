# 协议与可复现检索

## 问题与资格标准

按学科选择问题框架，例如干预问题可用 PICO/PICOS，质性问题可用 PICo 或 SPIDER，范围综述可用 PCC。框架是提示工具，不要为了填满字段扭曲研究问题。

协议至少记录：

- 目标与主要问题；
- 对象、暴露/干预、比较、结局或核心概念；
- 可接受的研究设计、发表类型、时间、语言和地域；
- 预印本、会议摘要、注册信息、灰色文献和重复报告的处理；
- 主要/次要结局、时间点及多报告选择规则；
- 筛选、提取、分歧处理、质量评价和综合方案；
- 计划偏离及其理由。

如果适用，建议在正式筛选前注册协议；注册与否不能替代方法透明度。

## 来源选择

根据问题领域选择互补的书目数据库、注册平台、预印本服务器、引文追踪和灰色文献来源。不存在“搜索固定三个数据库就自动完整”的规则。说明每个来源为何必要，并记录未能访问的重要来源。

通用网页搜索可用于发现术语、项目页或补充来源，但不能替代领域数据库覆盖。登录、订阅、API 密钥和付费检索必须由用户单独授权。

## 检索式构造

1. 从核心概念拆出受控词表与自由词同义词，包括缩写、旧称、拼写变体和关键术语。
2. 在概念内用 OR，概念间按问题逻辑用 AND；谨慎使用 NOT，防止误删相关记录。
3. 针对每个数据库语法转换，不把一条查询机械粘贴到所有平台。
4. 用已知应命中的关键研究进行试检，记录修订理由；试检不等于验证召回率。
5. 保存最终完整检索式，而不是只写关键词列表。

## 检索日志最低字段

| 字段 | 要求 |
|---|---|
| 来源/接口 | 数据库或平台准确名称 |
| 执行日期 | 使用绝对日期和时区（必要时） |
| 覆盖范围 | 平台可检索的年份/集合及本次限制 |
| 完整检索式 | 包含字段限定、过滤器和语法 |
| 命中数 | 该次查询返回的记录数 |
| 获取范围 | 实际导出的页数、游标或记录数 |
| 导出格式 | RIS、BibTeX、CSV、JSON 等 |
| 备注 | 错误、限流、访问缺口和查询修订 |

检索结果超过实际获取范围时，不能把命中总数当作已筛选数量。

## 更新与补充发现

记录最后检索日期；交付前若领域更新快，应复查是否需要更新检索。对纳入研究做前向/后向引文追踪，并记录追踪来源与日期。补充发现的记录仍须走同一纳排流程。
